# 架构决策记录

本文记录已经落地、并仍在约束代码的架构决策，供贡献者在改动前确认「为什么这样写」。D1–D17 是稳定锚点，新增决策顺延编号，不重排旧号。每条固定三段：决策、理由、影响。
### D1 运行时基线为 JVM 25
**决策**：所有模块 `jvmToolchain(25)`，产物 class 版本 69，不提供 Java 21 构建。
**理由**：多目标会让测试矩阵与依赖解析翻倍，而 25 已是当前宿主环境的常态。
**影响**：宿主 JVM 低于 25 直接无法加载，发布说明需写明。
### D2 退群解绑按群进行
**决策**：绑定表增加可空的 `source_group`。三个群内入口写入来源群号，游戏内命令与公开 API 写入 NULL；退群只解绑来源为本群的行。
**理由**：一个 QQ 号可绑多个角色，退一个群不该清空全部绑定。
**影响**：NULL 行保留并在每群首次遇到时 WARN；升级前的历史行需要管理员手动清理。
### D3 远程控制台不做命令黑名单
**决策**：不做 deny 列表，只做限流、输出截断、ANSI 归一化与审计；权限由 `admins` 名单加 `COMMAND_DISPATCH` 能力共同决定。
**理由**：白名单式授权比穷举危险命令更可维护，黑名单永远漏。
**影响**：授予管理员即等价于授予控制台，授予前需确认对方可信。
### D4 Hytale 依赖不固定版本
**决策**：`hytale` 模块使用 `com.hypixel.hytale:Server:+`，不在构建脚本里钉版本。
**理由**：上游尚未稳定发版，钉死会让插件在宿主小版本更新后直接不可用。
**影响**：产物不可完全复现，发布说明需列出已验证的宿主版本区间。
### D5 模板版本化并强制校验和
**决策**：模板 manifest 声明 `protocol` 与 `routes`；`template_sha256` 非空时必须匹配，协议号不一致直接拒绝。
**理由**：模板是渲染输入的一部分，静默漂移会让同一配置产出不同图片。
**影响**：模板升级要与插件版本同步发布校验和，否则用户看到的是明确失败而不是错误图片。
### D6 Playwright 沙箱默认开启
**决策**：Chromium 沙箱默认开启，配置键是反向的 `render.playwright.disable_sandbox`。
**理由**：默认安全，需要放宽的部署显式声明。
**影响**：容器或受限内核环境需手动关闭沙箱，否则浏览器起不来。
### D7 Gson 不重定位
**决策**：产物保留 `com/google/gson` 原包名，`checkRelocation` 对其显式豁免。
**理由**：接受宿主自带的 Gson，避免重定位后出现两份类导致版本冲突。
**影响**：与宿主 Gson 版本共存的问题由部署方验证；其余第三方库仍统一重定位。
### D8 语义变更走弃用周期
**决策**：公开成员不直接删除，先标 `@Deprecated` 并在主版本内保留。
**理由**：第三方插件按契约编译，直接删除会造成二进制不兼容。
**影响**：目前仍保留数个零调用但已弃用的成员，清理要等下一个主版本。
### D9 远程控制台审计默认记录完整指令
**决策**：审计默认写入完整指令文本，`remote_console.log_commands=false` 可关闭内容、只留元信息。
**理由**：排障需要还原现场，而日志本身受宿主权限保护。
**影响**：对指令内容敏感的场景需主动关掉，文档与示例配置都要提示。
### D10 Adventure 由宿主提供
**决策**：产物不内联、不重定位 Adventure 与 MiniMessage；Hytale 缺少时由 Libby 运行期按原包名装载。`/plumbot` 的语义统一在 `common` 的命令处理器里，平台层只把结果落成 Component 或纯文本。
**理由**：跨 API 传递 `Component` 时，插件自带一份会导致类身份不同而报错。
**影响**：宿主必须提供 Adventure；新增平台时要显式声明这一点。
### D11 Hytale 群消息双写
**决策**：Hytale 侧群消息同时走 Universe 播报与 `ConsoleSender`，`feature.message.console_echo` 默认开启，键缺失视为开启。
**理由**：Hytale 的聊天回显通道不统一，只写一边会有玩家看不到。
**影响**：关闭该键会失去控制台侧回显，排查消息丢失时先看这里。
### D12 模板下载多候选回退
**决策**：官方直链打头；起点是 GitHub 时追加 ghproxy.net、gh-proxy.com、ghfast.top 三个镜像。`template_urls` 非空时完全覆盖单模板配置。
**理由**：部分地区直连不可达，硬编码单地址等于不可用。
**影响**：镜像失效只影响下载，不影响已缓存模板；自定义镜像需自行承担完整性风险。
### D13 日志可见性分级
**决策**：Hytale 的 DEBUG/TRACE 提升为 INFO 并加 `[DEBUG]`/`[TRACE]` 前缀；`runSync` 排入真实世界 tick 队列；下载过程压缩为开始与完成各一行 INFO。
**理由**：宿主缺少分级日志通道，刷屏会淹没真正有用的信息。
**影响**：排障时可读，但高流量服务器上仍应控制 DEBUG 类日志的调用频率。
### D14 校验和不匹配直接失败
**决策**：`template_sha256` 不匹配即报错并保留旧模板，不换镜像重试。
**理由**：校验失败意味着内容被篡改或镜像错误，换源重试只会掩盖问题。
**影响**：模板更新必须同步更新校验和，否则会看到持续失败。
### D15 网络出口仅 https 且逐跳校验
**决策**：只允许 https，起点主机必须在白名单内，重定向手动逐跳校验（上限 20 跳）；不再做解析后 IP/CIDR 判定，也不做终态白名单复核；不为此新增配置键。
**理由**：IP 判定挡不住 DNS 重绑定，逐跳主机校验语义更清晰。
**影响**：见「已知限制」中的重绑定残余窗口。
### D16 Playwright 装载门
**决策**：装载由状态机与单飞保护，成功后不再触发，失败冷却 60 秒；渲染路径只调度装载、绝不内联下载；主线程守卫放在装载器侧。
**理由**：下载动辄数百 MB，内联会直接卡死 tick。
**影响**：冷却期内渲染走 AWT 且只记 INFO，`/plumbot render doctor` 可看剩余秒数。
### D17 登录校验缓存优先且 fail-closed
**决策**：登录白名单校验缓存优先，TTL 默认 300 秒、负缓存 30 秒、陈旧正缓存最多复用 60 秒、同名单飞，最多等待 500 毫秒（钳制 50–5000）；超时、异常、库未就绪一律拒绝并计 `LOGIN_LOOKUP_UNAVAILABLE`。
**理由**：放错人进来不可逆，挡错人可由管理员手动补绑恢复。
**影响**：数据库故障会表现为所有人都进不来；应急时关闭 `feature.bind.whitelist`。

## 已知限制与已接受的残余风险

- **DNS 重绑定窗口**：HTTP 客户端基于 `HttpURLConnection`，没有自定义 DNS 解析入口，无法做到「校验哪个 IP 就连哪个 IP」。攻击者需同时控制白名单域名的 DNS 并命中校验与连接之间的时序窗口。缓解措施：出口仅 https、逐跳校验重定向起点与目标的主机名、起点主机白名单（`render.avatar.domains`、`render.playwright.template_urls`）、下载体量与 sha256 校验、图片格式嗅探。发布说明必须声明此残余风险。
- D15 放宽后的残余面：白名单内主机被攻陷或 CDN 被劫持时，下载可被引向任意 https 主机；http 内网目标（含云元数据地址）仍然到不了。
- 控制台回显的 ANSI 与颜色透传是宿主通道差异，Hytale 侧依赖 D11 的双写。
- MySQL 的索引建立属静默路径：探测语句或权限假设错误时，插件仍能正常启动，只是索引未建。
- `source_group` 为 NULL 的历史绑定行在退群时永远解不掉，只能手动清理。
- 装载门冷却的 60 秒内拒绝重试，此时渲染降级为 AWT；这是有意的退避，不是故障。

## 明确不做

不做构建期的 legacy 门控校验、不做公开 API 的签名基线、不引入 WebP、不引入 OkHttp（见 DNS 重绑定限制）、不为修复上述限制新增配置键。已有的公开成员即使零调用，也只走弃用流程（D8）。
